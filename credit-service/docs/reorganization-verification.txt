Credit organization verification, 18 October 2026.
Scope. Behavior-preserving source reorganization only. Four tables, JSON result, SQL, locks and transaction boundaries retained.
Structure. credit contains commands, accounts, queries, types and shared CreditOrder persistence. events contains outbox and Pub/Sub infrastructure. db contains connection/locking and migration. Root retains HTTP/auth/config/startup/backfill.
Equivalence. The baseline and new implementations ran the same deterministic scenario in the disposable PostgreSQL database at 127.0.0.1:5437. Random transaction IDs were normalized; request IDs, codes, status, amounts, deltas, balances, ledger bucket movements and outbox business payloads were compared. Event IDs and timestamps were excluded because they are generated per execution.
Source comparison. Function bodies were compared ignoring whitespace and explicit helper renames. The grant validator formerly in the constructor remains at startup/backfill and is called by the exported event handler.
Commands. npm test; npm run typecheck; npm run pubsub:provision; npm run test:pubsub. Compose used compose.yaml and credit-service/compose.verify.yaml with up -d --build credit-service credit-publisher, then test/compose.mjs through the rebuilt API container.
Limit. Pub/Sub uses the local emulator; production Google IAM was not exercised.
